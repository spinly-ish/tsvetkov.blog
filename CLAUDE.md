# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Local Preview

```bash
python3 scripts/build.py  # regenerate generated sections
python3 -m http.server 8000
```

Minimal build step via Python 3 (stdlib only, zero `node_modules`). After editing `data/posts.json` or any BUILD-marked block, run `build.py` before previewing.

After adding a new post, always start the server so the user can preview before committing.

## Architecture

Hybrid static site: hand-written post bodies + generator-controlled metadata/lists.

```
tsvetkov.blog/
├── data/posts.json        # single source of truth (metadata, excerpts)
├── scripts/
│   ├── build.py           # Python 3 generator, zero deps
│   ├── theme.js           # theme toggle (external)
│   └── search.js          # index-page search (external)
├── index.html             # EN home, contains BUILD markers
├── ru/index.html          # RU home, contains BUILD markers
├── posts/*.html           # EN posts, BUILD:META markers in <head>
├── ru/posts/*.html        # RU posts, BUILD:META markers in <head>
├── sitemap.xml            # generated
├── feed.xml               # generated RSS (EN)
├── ru/feed.xml            # generated RSS (RU)
├── styles.css             # one stylesheet for everything
└── pics/                  # images (absolute paths from all pages)
```

### BUILD markers

Sections of HTML between these comments are regenerated by `build.py`:

- `<!-- BUILD:META_START -->` … `<!-- BUILD:META_END -->` — description, title, canonical, OG, Twitter Card, JSON-LD, hreflang (in both indexes and all posts).
- `<!-- BUILD:POSTS_START -->` … `<!-- BUILD:POSTS_END -->` — list of `<article class="blog-post">` cards on `index.html` and `ru/index.html`.

**Never edit content between these markers manually — it will be overwritten on the next build.** Edit `data/posts.json` and re-run `build.py`.

Post bodies (`<article class="post-content">`) are NOT inside markers and are edited by hand.

## Deployment

GitHub Pages via `.github/workflows/deploy.yml`:
- Triggered on `push` to `main` and `workflow_dispatch`.
- CI runs `python3 scripts/build.py`, then `actions/upload-pages-artifact` + `actions/deploy-pages`.
- Requires `Settings → Pages → Build and deployment → Source: GitHub Actions` (not "Deploy from branch").

The `docs/` folder is gitignored and never deployed. `.nojekyll` at repo root disables Jekyll processing.

**You don't have to run `build.py` before push** — CI does it. But running locally before commit is still good practice so the diff reflects what'll ship. The workflow warns if committed output differs from fresh build.

## Bilingual Structure

```
tsvetkov.blog/           → EN homepage
tsvetkov.blog/ru/        → RU homepage
tsvetkov.blog/posts/     → EN posts
tsvetkov.blog/ru/posts/  → RU posts
```

Path conventions:
- `ru/index.html` uses `../styles.css`, `/pics/` (absolute) for images, `/scripts/*.js` (absolute)
- `ru/posts/*.html` uses `../../styles.css`, `/pics/`, `/scripts/*.js`
- All RU pages have `<html lang="ru">` and back-links to `/ru/`

Hreflang alternates are generated by `build.py` into the BUILD:META block — don't edit them by hand.

Language switcher (`.lang-toggle` in `.search-container`) shows **EN** | RU on English pages and EN | **RU** on Russian pages. This part is hand-maintained (per-file slug in href).

## Adding a New Post

1. **Create** `posts/<slug>.html` — copy any existing EN post as a template. Edit the body (`<article class="post-content">`) and the `<header class="post-header">` (date, title, lang-toggle href). Leave the BUILD:META block as-is — it'll be regenerated.
2. **Create** `ru/posts/<slug>.html` — same, using `../../styles.css` and back-link to `/ru/`.
3. **Add entry** to `data/posts.json`:
   ```json
   {
     "slug": "<slug>",
     "date": "YYYY-MM-DD",
     "read_time_min": N,
     "image": "/pics/filename.jpg",
     "en": {"title": "...", "description": "...", "excerpt": "...", "image_alt_card": "...", "image_alt_post": "..."},
     "ru": {"title": "...", "description": "...", "excerpt": "...", "image_alt_card": "...", "image_alt_post": "..."}
   }
   ```
4. **Run** `python3 scripts/build.py`. Verify the index lists the new post, the post page has correct meta tags, `sitemap.xml` and `feed.xml` updated.
5. **Preview** locally: `python3 -m http.server 8000`.

## Post HTML Structure

- `<time datetime="YYYY-MM-DD">` in the post header (hand-edited).
- `<img loading="lazy" decoding="async" src="/pics/filename" ...>` — images live in `/pics/`, always lazy.
- Post filename = URL slug = key in `posts.json`.
- `<script src="/scripts/theme.js" defer></script>` at the bottom of `<body>` (not inside markers).

## Theming

CSS variables defined in `styles.css` under `:root` (light) and `[data-theme="dark"]`. Theme toggle lives in `scripts/theme.js`. The anti-flash inline script in each `<head>` stays inline — it must run synchronously before paint.

## Content Style

Russian is the primary language for new posts; English is secondary. Topics: product strategy, tech, behavior, simplicity vs complexity.

### Russian posts
Written by the author directly. Keep the original tone and text as-is.

### English posts
Mark Manson-inspired tone: direct, informal, punchy short paragraphs, conversational voice. Not a literal translation of the Russian — a rewrite that captures the same idea but sounds natural in English. Short sentences. A bit of attitude. No corporate speak.
