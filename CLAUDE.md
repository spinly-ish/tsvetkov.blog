This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Local Preview

```bash
/opt/anaconda3/bin/python3 scripts/build.py  # default --source=snapshot, no creds needed
/opt/anaconda3/bin/python3 -m http.server 8000
```

Default `--source=snapshot` reads `data/snapshot.json` (last successful Directus fetch, committed to repo). Local dev doesn't need Directus credentials.

To preview against live CMS:
```bash
source ~/.config/tsvetkov-blog/agent.env && \
  DIRECTUS_URL="$DIRECTUS_URL" DIRECTUS_TOKEN="$DIRECTUS_AGENT_TOKEN" \
  /opt/anaconda3/bin/python3 scripts/build.py --source=directus
```

Use `/opt/anaconda3/bin/python3` explicitly — homebrew's python3 doesn't see anaconda-installed `markdown` package (PEP 668).

After modifying any post via CMS or editing locally, start the server so the result can be eyeballed before committing.

## Architecture

Hybrid static site, CMS-driven: Directus on Railway → CI fetches → renders → GitHub Pages.

```
tsvetkov.blog/
├── data/
│   ├── snapshot.json      # last successful Directus fetch (CI fallback + local dev)
│   └── posts.json         # legacy, pre-cutover (kept for emergency rollback)
├── scripts/
│   ├── build.py           # Python 3 generator: --source={directus|snapshot|posts}
│   ├── migrate_to_directus.py  # one-shot, posts.json+HTML → Directus
│   ├── add_body_markers.py     # one-shot, wraps post bodies in BUILD:BODY markers
│   ├── theme.js
│   └── search.js
├── infra/directus/
│   ├── apply_schema.py    # idempotent schema/role/policy provisioner
│   ├── docker-compose.yml # local stand for prototyping
│   ├── README.md
│   └── RAILWAY.md         # step-by-step prod setup guide
├── index.html, ru/index.html  # BUILD:META + BUILD:POSTS markers
├── posts/*.html, ru/posts/*.html  # BUILD:META + BUILD:BODY markers
├── sitemap.xml, feed.xml, ru/feed.xml  # all generated
├── styles.css
└── pics/                  # images live in repo (NOT in Directus Files)
```

### BUILD markers

Sections of HTML between these comments are regenerated by `build.py`:

- `<!-- BUILD:META_START -->` … `<!-- BUILD:META_END -->` — description, title, canonical, OG, Twitter Card, JSON-LD, hreflang (in both indexes and all posts).
- `<!-- BUILD:POSTS_START -->` … `<!-- BUILD:POSTS_END -->` — list of `<article class="blog-post">` cards on `index.html` and `ru/index.html`.
- `<!-- BUILD:BODY_START -->` … `<!-- BUILD:BODY_END -->` — post body, rendered from Directus markdown via python-markdown + `_post_process_body()` (re-adds `loading="lazy"`, `class="post-image"`, `target="_blank" rel="noopener"`).

**Never edit content between these markers manually — it will be overwritten on the next build.** Edit data in Directus and re-run build (or let CI do it).

Post HTML skeleton outside markers (header, lang-toggle, footer) is hand-maintained.

## Deployment

GitHub Pages via `.github/workflows/deploy.yml`:
- Triggers: `push` to `main`, `workflow_dispatch`, `repository_dispatch: directus_publish` (sent by Directus Flow webhook on save).
- CI logic: if secrets `DIRECTUS_URL` + `DIRECTUS_BUILD_TOKEN` set → `build.py --source=directus`. Otherwise fallback to `--source=snapshot`.
- Requires `Settings → Pages → Build and deployment → Source: GitHub Actions`.

The `docs/` folder is gitignored. `data/snapshot.json` and `infra/` are stripped from the upload artifact. `.nojekyll` at repo root disables Jekyll processing.

## Bilingual Structure

```
tsvetkov.blog/           → EN homepage
tsvetkov.blog/ru/        → RU homepage
tsvetkov.blog/posts/     → EN posts
tsvetkov.blog/ru/posts/  → RU posts
```

Path conventions:
- `ru/index.html` uses `../styles.css`, `/pics/` (absolute) for images, `/scripts/*.js` (absolute)
- `ru/posts/*.html` uses `../../styles.css`, `/pics/`, `/scripts/*.js`
- All RU pages have `<html lang="ru">` and back-links to `/ru/`

Hreflang alternates are generated by `build.py` into the BUILD:META block — don't edit them by hand.

Language switcher (`.lang-toggle` in `.search-container`) shows **EN** | RU on English pages and EN | **RU** on Russian pages. This part is hand-maintained (per-file slug in href).

## Adding a New Post

Two prerequisites must be in place — both done **once per slug**, then the rest happens through CMS:

### One-time HTML skeletons

Directus owns the data, but each post still needs a thin HTML host file (header, footer, BUILD markers — `build.py` writes into them, doesn't create them):

1. **Create** `posts/<slug>.html` — copy any existing EN post as template. Replace the `<header class="post-header">` (date, title, lang-toggle href). Leave both BUILD:META and BUILD:BODY blocks empty (just markers) — `build.py` fills them.
2. **Create** `ru/posts/<slug>.html` — same, using `../../styles.css` and back-link to `/ru/`.

### Content via CMS (recurring path)

3. **Open** `https://cms.tsvetkov.blog/admin` → **Posts → + Create Item**.
4. **Fill in**:
   - `slug` (must match the HTML filename from steps 1-2)
   - `date` (YYYY-MM-DD), `read_time_min`, `image` (`/pics/filename.jpg`)
   - `status` = `published`
   - All `*_en` and `*_ru` fields, including `body_md_en` / `body_md_ru` (Markdown, no frontmatter)
5. **Save** → Directus Flow `Rebuild site on publish` → GitHub `repository_dispatch` → CI → site live in ~30-60s.

### Or via API (agents)

```bash
source ~/.config/tsvetkov-blog/agent.env
curl -X POST \
  -H "Authorization: Bearer $DIRECTUS_AGENT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"slug":"...", "date":"...", ..., "body_md_en":"# heading\n\n...", "status":"published"}' \
  "https://cms.tsvetkov.blog/items/posts"
```

Same webhook chain triggers.

## Post HTML Structure

- `<time datetime="YYYY-MM-DD">` in the post header (hand-edited skeleton).
- Header image inside BUILD:BODY is now rendered from Directus markdown — `build.py` post-process adds `loading="lazy" decoding="async" class="post-image"`.
- Post filename = URL slug = `slug` field in Directus.
- `<script src="/scripts/theme.js" defer></script>` at the bottom of `<body>` (not inside markers).

## Theming

CSS variables defined in `styles.css` under `:root` (light) and `[data-theme="dark"]`. Theme toggle lives in `scripts/theme.js`. The anti-flash inline script in each `<head>` stays inline — it must run synchronously before paint.

## Content Style

Russian is the primary language for new posts; English is secondary. Topics: product strategy, tech, behavior, simplicity vs complexity.

### Russian posts
Written by the author directly. Keep the original tone and text as-is.

### English posts
Mark Manson-inspired tone: direct, informal, punchy short paragraphs, conversational voice. Not a literal translation of the Russian — a rewrite that captures the same idea but sounds natural in English. Short sentences. A bit of attitude. No corporate speak.

## CMS (Directus on Railway)

Источник правды для контента — Directus на Railway (`https://cms.tsvetkov.blog`). Cutover выполнен 2026-05-10. Полный гайд по деплою/настройке: `infra/directus/RAILWAY.md`. Спека и post-mortem: `docs/План развития блога/10-cms-migration.md`.

### Data flow

```
Author / Agent → Directus admin или REST API
                        ↓
                 Directus Flow «Rebuild site on publish»
                        ↓ POST /repos/spinly-ish/tsvetkov.blog/dispatches
                 GitHub Actions deploy.yml
                        ↓ build.py --source=directus
                        ↓ Markdown→HTML, post-process (img/link attrs)
                        ↓ commit data/snapshot.json
                 GitHub Pages → tsvetkov.blog
```

### Secrets (GitHub Actions)

- `DIRECTUS_URL` = `https://cms.tsvetkov.blog`
- `DIRECTUS_BUILD_TOKEN` = read-only token of `build` role in Directus

Если секретов нет — CI собирает `--source=snapshot` (контент из последнего успешного фетча).

### Tokens (local)

`~/.config/tsvetkov-blog/agent.env` хранит `DIRECTUS_URL` и `DIRECTUS_AGENT_TOKEN` (роль `agent` с CRUD на posts/site_config). Файл вне репо. Используется для запуска `migrate_to_directus.py`, `build.py --source=directus` и API-операций агентов.
